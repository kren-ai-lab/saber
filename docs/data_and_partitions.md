# Data and partitions

## DatasetBundle

`DatasetBundle` is the canonical supervised-data contract.

```text
DatasetBundle
├── X
├── y
├── sample_ids
├── feature_names / FeatureSchema
├── groups
├── sample_weight
└── metadata
```

`X` must be numerical and two-dimensional. `y` is single-target. Missing feature values may remain so that imputation can happen safely inside folds; infinities are rejected. Classification targets must resolve to binary or multiclass semantics.

### Stable sample identity

Partitions refer to `sample_ids`, never to assumptions about current row order. `DatasetBundle.subset()` preserves the original dataset order while selecting membership by identity.

### FeatureSchema

`FeatureSchema` stores ordered feature names and dtypes. Persisted models use it to reject inference matrices with missing, extra, or reordered features.

### Fingerprints

`dataset.fingerprint` is a deterministic hash of scientific content: features, targets, sample IDs, feature identity, groups, and sample weights. Free-form metadata is excluded.

## PartitionPlan

A `PartitionPlan` is one or more explicit `PartitionSplit` objects:

```text
PartitionSplit
├── train_ids
├── validation_ids
└── test_ids
```

The contract rejects duplicate membership, within-split overlap, unknown IDs, and fingerprint mismatches. Complete coverage can be required or deliberately relaxed.

### Holdout

```python
from saber.datasets import PartitionPlan

plan = PartitionPlan.holdout(
    train_ids=train_ids,
    validation_ids=validation_ids,
    test_ids=test_ids,
    dataset_fingerprint=dataset.fingerprint,
)
```

For a train/validation/test plan, `evaluation_role="auto"` protects the final test where the workflow supports that distinction.

### Predefined folds

```python
plan = PartitionPlan.from_predefined_folds(
    sample_ids=dataset.sample_ids,
    fold_assignments=fold_ids,
    dataset_fingerprint=dataset.fingerprint,
)
```

`-1` follows sklearn-style “always train, never validation” semantics by default.

## BioSieve integration

When the data are not already partitioned, **BioSieve is the canonical partition-generation engine**.

```python
from saber.datasets import BioSievePartitionConfig

partitioning = BioSievePartitionConfig(
    strategy="stratified_kfold",
    params={"n_splits": 5, "seed": 42},
)
```

The integration preserves BioSieve strategy, effective parameters, statistics, and memberships in the resulting `PartitionPlan`.

### Responsibility boundary

```text
raw/domain data
      │
      ├── optional BioSieve redundancy reduction (upstream)
      ▼
prepared numerical representation
      │
      ├── existing partitions ─────────────┐
      │                                    │
      └── BioSieve split generation ───────┤
                                           ▼
                                      PartitionPlan
                                           ▼
                                         saber
```

Saber does **not** implement redundancy reduction, sequence identity, MMseqs2 reduction, clustering for representative selection, or parallel fallback splitters.

## External partitions

JSON/CSV/TSV/DataFrame partition tables can be normalized through `load_partition_plan()` / `partition_plan_from_frame()`. This makes partitions generated by external scientific tooling first-class inputs without silently recreating them.
