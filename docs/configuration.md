# YAML/JSON configuration

A config file describes one workflow with the same arguments as the Python function of the same
name (`saber.train`, `saber.validate`, `saber.tune`, `saber.evaluate`, `saber.predict`,
`saber.benchmark`). Run it with `saber run config.yaml`, or from Python with
`saber.run_config("config.yaml")` (a path, a mapping, or a `WorkflowConfig` from
`saber.config.load_config`).

## Conventions

- `schema_version: "2.0"` and `workflow` come first. Schema `1.0` configs are rejected.
- Keyword arguments of the Python function are top-level keys: `algorithm`, `model_params`,
  `preprocessing`, `metrics`, `evaluation_role`, `require_complete`, `positive_class`,
  `random_state`.
- Config objects are nested blocks with the fields of their class: `preprocessing`
  (`PreprocessingConfig`), `tuning` (`TuningConfig`), `benchmark` (`BenchmarkConfig`) and
  `partitioning` (`BioSievePartitionConfig`).
- `artifact: PATH` is where `train`/`tune` save the model (`saber.save_model`); `model: PATH` is the
  saved model that `evaluate`/`predict` read.
- `output: DIR` is a results directory (see [Output files](#output-files)).
- `artifact` and `output` must not exist yet unless `overwrite: true`.
- `metadata` is a free mapping stored with saved models and benchmarks.
- Relative paths are resolved against the config file location.
- Unknown keys are errors.

## Datasets

```yaml
dataset:
  path: data/features.csv    # .csv, .tsv, .txt (tab-separated) or .parquet
  target_col: label          # required except for predict
  sample_id_col: sample_id
  group_col: patient         # DatasetBundle.groups
  sample_weight_col: weight  # DatasetBundle.sample_weight
  feature_cols: [f0, f1, f2] # default: every other column
  sep: ";"                   # overrides the text separator
```

Only `path` is required. Without `feature_cols`, all columns except the target, sample-id, group,
sample-weight and partitioning columns (`seq_col`, `cluster_col`, `date_col`,
`extra_columns`) are features.

## Partitions

`validate` and `tune` take exactly one of `partition_plan` (an existing file, read with
`saber.load_partition_plan`) or `partitioning` (generated by BioSieve, which needs `saberlib[biosieve]`):

```yaml
partition_plan:
  path: partitions.csv       # .json (PartitionPlan.to_dict()), .csv or .tsv
  sample_id_col: sample_id   # the keyword arguments of load_partition_plan
  role_col: role             # membership layout: train / validation / test
  split_col: split
  # fold_col: fold           # or the predefined-fold layout
  # always_train_value: -1
```

```yaml
partitioning:
  strategy: stratified_kfold
  params: {n_splits: 5, seed: 42}   # BioSieve splitter parameters
  seq_col: sequence                 # optional: seq_col / cluster_col / date_col name dataset columns
  extra_columns: [organism]         # other dataset columns the strategy needs; never features
```

`benchmark` takes `partitions` (a mapping of label to partition file) or `partitioning`.

## Output files

| Workflow | Files written into `output` |
|---|---|
| `train` | `summary.json` |
| `validate` | `summary.json`, `metrics.csv` (per split), `predictions.csv` (out-of-fold) |
| `tune` | `summary.json`, `optimization_history.csv` |
| `evaluate` | `summary.json`, `metrics.csv` |
| `predict` | `summary.json`, `predictions.csv` |
| `benchmark` | the `saber.save_benchmark` directory: `runs.csv`, `metrics.csv`, `predictions.csv`, `failures.csv`, `optimization_history.csv`, `benchmark_metadata.json`, manifest and checksums |

## train

```yaml
schema_version: "2.0"
workflow: train
dataset: {path: data/train.csv, target_col: label, sample_id_col: sample_id}
algorithm: random_forest_classifier
model_params: {n_estimators: 300}
preprocessing: {imputation: median, scaler: none}
positive_class: 1
random_state: 42
partition_plan: {path: folds.json}   # optional: recorded in the artifact as provenance
artifact: artifacts/model
output: results/train
overwrite: false
metadata: {study: demo}
```

## validate

```yaml
schema_version: "2.0"
workflow: validate
dataset: {path: data/train.csv, target_col: label, sample_id_col: sample_id}
algorithm: logistic_regression
model_params: {C: 0.5}
preprocessing: {imputation: auto, scaler: auto}
partitioning:
  strategy: stratified_kfold
  params: {n_splits: 5, seed: 42}
metrics: [mcc, balanced_accuracy, roc_auc]
evaluation_role: auto        # auto, validation or test
require_complete: true
positive_class: 1
random_state: 42
output: results/validate
```

## tune

```yaml
schema_version: "2.0"
workflow: tune
dataset: {path: data/train.csv, target_col: label, sample_id_col: sample_id}
algorithm: logistic_regression
partition_plan: {path: folds.json}
tuning:
  optimizer: random          # grid, random, halving_grid, halving_random or optuna
  n_iter: 10
  refit_metric: mcc          # default: the first metric
search_space:
  C: {type: log_float, low: 0.01, high: 10.0}
  class_weight: [null, balanced]
metrics: [mcc, balanced_accuracy]
evaluation_role: auto
require_complete: true
positive_class: 1
random_state: 42
artifact: artifacts/tuned_model
output: results/tune
```

Search-space domains are lists or typed mappings: `categorical` (`values`), `integer`
(`low`, `high`, `step`), `float` (`low`, `high`, `step`), `log_float` (`low`, `high`).

## evaluate

```yaml
schema_version: "2.0"
workflow: evaluate
model: artifacts/model
dataset: {path: data/test.csv, target_col: label, sample_id_col: sample_id}
metrics: [mcc, roc_auc]
positive_class: 1
strict_environment: false    # passed to saber.load_model
output: results/evaluate
```

## predict

```yaml
schema_version: "2.0"
workflow: predict
model: artifacts/model
dataset: {path: data/new.parquet, sample_id_col: sample_id}
positive_class: 1
strict_environment: false
output: results/predict
```

## benchmark

```yaml
schema_version: "2.0"
workflow: benchmark
datasets:                    # label -> dataset; one representation is a one-entry map
  descriptors: {path: data/descriptors.csv, target_col: label, sample_id_col: sample_id}
  embeddings: {path: data/embeddings.parquet, target_col: label, sample_id_col: sample_id}
algorithms: [logistic_regression, random_forest_classifier]
model_params:                # algorithm -> parameters, as in saber.benchmark
  random_forest_classifier: {n_estimators: 300}
partitioning:                # tuned runs need one train/validation/test holdout
  strategy: stratified
  params: {test_size: 0.2, val_size: 0.2, seed: 42}
partitioning_reference: descriptors   # dataset the BioSieve partitions are generated from
benchmark:
  seeds: [42, 123]
  modes: [untuned, tuned]
  include_baselines: true
  tuning: {optimizer: grid, refit_metric: mcc}
search_spaces:               # algorithm -> search space, for tuned runs
  logistic_regression:
    C: [0.1, 1.0, 10.0]
metrics: [mcc, balanced_accuracy]
evaluation_role: auto
require_complete: true
positive_class: 1
output: results/benchmark
```

With existing partition files, replace `partitioning`/`partitioning_reference` by
`partitions: {external_cv: {path: folds.json}}`. Without `partitioning_reference`, BioSieve
partitions are generated from the first dataset.

## Checking a config

```bash
saber run experiment.yaml --dry-run
```

`--dry-run` validates the config and shows the plan without running anything.

Runnable files live in [`examples/configs/`](../examples/configs/).
